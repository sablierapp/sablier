{{- /* Keeps the sidebar where the reader left it across page loads: which sections are expanded (localStorage, survives visits) and how far it is scrolled (sessionStorage, this tab only). Every sidebar link is a full page load, so this state has to be put back before the browser paints the new page. Waiting for DOMContentLoaded is too late: that event waits for every deferred script (analytics, search, mermaid), so the page would first paint with Hextra's defaults and then visibly snap. This partial is therefore rendered immediately after the sidebar partial and runs synchronously while the page is still being parsed. Hextra's sidebar.js then calls scrollToActiveItem() on DOMContentLoaded, which scrolls the active item to the top and would undo the restore. When we have restored a position that keeps the active item in view, we swallow that one scrollTo call; otherwise Hextra's own behaviour is left untouched. Include it right after `partial "sidebar.html"` in every layout that renders the docs sidebar (layouts/docs/single.html and layouts/docs/list.html). */ -}}
